# Topic 需求说明

记录需求正文及来源，不维护实体状态/归属。已有权威需求引用原文，本文件只保留当前 Topic 的差异；TASK_CONTEXT 保留入口而不复制全文。未知可留待确认。

## 需求来源与目标

用户请求、已有产品说明或决定；要解决谁的什么问题，预期成果是什么。

## 使用场景与行为

使用者/输入、触发条件、正常行为、边界和失败行为。无交互成果说明其消费者与使用方式。

## 范围与非目标

本次包含/排除的能力、交付物和明确边界。调查/设计交付与产品实现分别说明。

## 可观察验收条件

为条件分配稳定引用（如 AC-1），写清输入/环境、预期结果和判断依据；需要用户人工验收的条件明确标出。

## 约束、依赖与影响

已有架构/接口、环境与质量约束、相关 Topic 或外部依赖；状态和成员用系统查询，不另建实时列表。

## 未知、取舍与需求变更

待回答问题、决定者、阻塞范围和验证去向；需求调整的原因、已有决定及受影响判据，保留来源，不把失败改名为通过。
