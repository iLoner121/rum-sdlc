# 开发方案

所属 Topic、目标分支和依赖引用系统查询。此文是拟议/实施中的方案，不代表功能已实现；D1—D6 / A1—A4 的分流判定及实施前检查结论统一写在 TASK_CONTEXT.md，此处引用而不重复维护。已有 DESIGN 后继续在本文件修订。

## 基线、需求与验收映射

有代码时记录目标 SHA/未提交变化，无代码时记录成果/资料版本；每个验收项对应实现机制和验证证据。

## 现状、影响范围与架构约束

模块、接口、数据、其他相关 Topic；引用有效约束/决策，区分事实与假设。

## 方案与取舍

数据所有权、交互/更新流程、接口和边界行为。真实取舍的理由与代价。命中 A1—A4 的长期决策链接 docs/decisions 的主记录，不重复保存其正文；未命中的实现选择及理由写在此处。

## 实施路径与迁移

局部结果、先后依赖、旧数据/调用方兼容；链接已确定的实现/验证活动，不提前铺满所有 Task。形成/修订本方案的 design Task 保存过程并链接本文件，不复制方案正文。

## 验证计划

测试、运行/交互场景、性能测量及整合验证；标明需要用户人工验证的部分。

## 未知项与冲突

双方、具体不兼容点、证据、影响、处理决定/待决定事项、验证方法与阻塞范围；没有发现时说明核对范围，不声称保证不存在冲突。

## 方案修订与最终偏差

记录影响实现的变更原因、决定和证据；交付时核对实际结果与方案差异。

非 Git 项目有真实代码时，用实际文件内容基线（例如交付副本或文件校验清单）、测试环境/结果和交付记录定位证据。不得因无 Git 改填 no_code，也不虚构分支或提交 SHA；Git 专用检查仅适用于 Git 项目。
