# Topic 需求与 PRD

PRD 是需求正文，不是新实体、批准凭证或生命周期台账。先明确用户目标、范围和可观察的验收条件，再开展依赖它们的正式实现；调查活动可先解决具体未知。

## 放置与单一正文

用户要求独立 PRD、交付物包含需求文档、需要独立需求评审，或多条外部行为/验收边界需要集中协调时，用 document 的 prd 字段定位 PRD.md，按 [prd.md](../assets/prd.md) 写入。已有权威需求直接引用，当前 Topic 只写对应范围/差异，不重抄成另一个主版本。

目标和行为已明确、无需独立需求文档时，在 TASK_CONTEXT 的目标/验收区保留简明需求即可，并说明未单独建 PRD 的依据。存在未知不代表先生成空 PRD 就已完成需求分析。

独立 PRD 建立后，上下文只保留目标摘要与链接；验收记录引用判据 ID/来源，不复制需求全文。需求变化更新权威正文，记录决定与影响，复核设计、检查映射和已接受结论；不通过改判据隐藏失败。

## 内容与活动

至少覆盖：真实来源与目标、使用者/触发场景、范围与非目标、行为/边界、验收判据、约束/依赖、未知及决定。纯调查/设计交付写清结论/证据要求，不声称代码实现完成。

形成/澄清需求按实际目的使用调查、设计或过程活动，不新增强制需求 Task 类型。用户仅认可需求不自动批准架构取舍、整批实施、具体 Git 提交或最终交付。
