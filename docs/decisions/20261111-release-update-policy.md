# RumSDLC 发行版本与本地更新边界

日期：2026-11-11；所属 Topic：T18。
状态：accepted（仅下列已确认政策，尚未实现）。用户后续已明确认可技术方案并要求实现和发布；实现与验收证据见 T18 管理记录。原先的技术工具、版本细则和通知实现为 proposed，见工程管理数据中的 T18 DESIGN.md；本记录不把拟议方案整体认定为已接受。

## 背景与选项
程序发行版本固定，主干不同构建缺少身份，合并不自动形成可安装 Release。比较手动升版、每次符合条件合并即自动发布、自动准备发布 PR 后确认三种方式；用户选择第三种。比较系统级常驻检查和复用 daemon；用户选择已有 daemon 且默认关闭。

## 已确认决定

1. RumSDLC 程序发行版本采用 SemVer 表达影响，发布 PR 负责自动准备版本与变更说明，由维护者确认后正式发布。普通功能合并不等于正式发布。
2. 构建身份与发行版本区分，主干构建能显示来源；工作流数据协议版本独立推进，不随程序版本机械递增。
3. 更新查询与安装分离。每小时检查复用现有后台服务，默认关闭；发现更新仅提示，用户主动调用安装入口。
4. 本体更新不隐式更新工程规则/数据，不自动启用服务或同步；安装继续使用原有事务、互斥和恢复边界。

决定依据：本会话用户明确选择「自动准备发布 PR，确认后正式发布」「采用现有后台服务，默认关闭」；在解释 SemVer 与发布 PR 各自职责后，用户答复「OK，没问题，出技术方案吧」。适用 RumSDLC 发布/安装/自更新流程；未替代项目身份和 Topic 编号两项既有决策。

## 代价与后续评审
维护者保留确认发布的一次操作，需维护自动化凭据与平台产物门禁；daemon 未运行时不承诺常驻检查；开发构建不能只凭 SemVer 数值比较作回退决定。

Release Please 选型、严格 0.x 升版细则、通知渠道、数据接口、安装 helper 及权限配置是拟议技术方案，不属于本条已确认政策。本轮已实现 release.Identity、internal/update、原生安装协作者和专属发布工作流；三端 CI 及真实发布证据完成后写入 T18 acceptance，未完成前不声称最终交付。
